## 1. SQL 核心

**逻辑执行顺序**：`FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`
（WHERE 里不能用 SELECT 别名；对聚合筛选用 HAVING；窗口函数只能进 SELECT/ORDER BY，要过滤就包子查询）

```sql
-- 反连接："没有 X 的 Y"
SELECT u.* FROM users u
LEFT JOIN orders o ON o.user_id = u.id AND o.status = 'pending'
WHERE o.id IS NULL;

-- 每组 Top-N
SELECT * FROM (
    SELECT t.*, row_number() OVER (PARTITION BY 分组列 ORDER BY 排序列 DESC) AS rn
    FROM t
) x WHERE rn <= 3;

-- 累计 / 环比
sum(x) OVER (ORDER BY d)                                   -- 累计
lag(x) OVER (ORDER BY d)                                   -- 上一行
x - lag(x) OVER (ORDER BY d)                               -- 环比增量

-- UPSERT（依赖唯一约束）
INSERT INTO t (k, v) VALUES (1, 'a')
ON CONFLICT (k) DO UPDATE SET v = EXCLUDED.v RETURNING *;

-- 条件聚合
count(*) FILTER (WHERE cond)
```

**NULL 三值逻辑**：`NULL = NULL → NULL`；判断只能 `IS [NOT] NULL`；`NOT IN` 子查询含 NULL 全灭 → 用 `NOT EXISTS`。

**IN vs EXISTS**：子查询小用 IN；外表小/子查询大用 EXISTS；「不存在」永远 NOT EXISTS。

## 4. 索引速查

**B-tree 适用**：等值 / 范围 / 前缀 LIKE / ORDER BY。**不适用**：函数包裹、`%x%`、jsonb `@>`、类型不匹配。

| 需求 | 索引写法 |
|---|---|
| 常规等值/范围 | `CREATE INDEX ON t (col);` |
| 多条件+排序 | `CREATE INDEX ON t (等值列, 范围/排序列);`（最左匹配：连续前缀才定位） |
| 免回表 | `CREATE INDEX ON t (k) INCLUDE (查的列);` → Index Only Scan |
| 只查少数行 | `CREATE INDEX ON t (col) WHERE 状态='pending';`（部分索引，小且快） |
| 函数查询 | `CREATE INDEX ON t (lower(email));`（表达式要一字不差） |
| LIKE 'abc%' | `CREATE INDEX ON t (col text_pattern_ops);` |
| LIKE '%x%' | `CREATE EXTENSION pg_trgm; CREATE INDEX ON t USING gin (col gin_trgm_ops);` |
| jsonb @> | `CREATE INDEX ON t USING gin (tags [jsonb_path_ops]);` |
| 业务防重 | `CREATE UNIQUE INDEX ...;`（UPSERT 依赖） |

**失效/弃用清单**：函数包裹列（`::date`、`lower()`）、`::text` 强转、前导 `%`、违反最左匹配、范围断档后的列、命中比例太高（>5~10% planner 正确地选 Seq Scan）、统计过期（`ANALYZE t;`）。

**代价**：写放大 + 空间 + 拖累 UPDATE；无用索引排查：
`SELECT * FROM pg_stat_user_indexes WHERE idx_scan = 0 AND indexrelname NOT LIKE '%_pkey';`

**PG 外键不自动建索引**（MySQL 会）——按外键查的路径都要自己建。

## 5. EXPLAIN 速查

```sql
EXPLAIN (ANALYZE, BUFFERS) <SQL>;   -- 学习期默认这么跑（UPDATE/DELETE 要包 BEGIN...ROLLBACK）
```

| 节点 | 含义 | 看什么 |
|---|---|---|
| Seq Scan | 全表顺序扫 | Rows Removed 巨大 → 缺索引；命中率高 → 正常 |
| Index Scan | 索引定位+回表 | Index Cond（用上索引的条件）vs Filter（没用上的） |
| Bitmap Scan | 位图批量回表 | 几百~几万行的中间态 |
| Index Only | 免回表 | Heap Fetches=0 最佳 |
| Sort | 排序 | 排序列配索引可消除；Batches>1 = spill 磁盘 |
| Nested Loop / Hash / Merge | 三种 Join | 小外层+内层索引 / 大等值 / 大且有序 |

**估算 rows vs actual rows 差 10 倍+ → 统计信息过期 → ANALYZE。**
**cost 只用于比较无绝对意义；actual time × loops 才是真耗时。**

## 6. 慢查询五步法

```
① pg_stat_statements（或慢日志）找到慢 SQL
② EXPLAIN (ANALYZE, BUFFERS)
③ 定位瓶颈：全表扫？Filter 里的失效条件？Sort spill？估算失真？
④ 加索引（套第 4 节模板）或改写（范围化、keyset 分页、去函数包裹、NOT EXISTS）
⑤ 重跑验证：计划变了 + 耗时降了 + 结果一致
```

深分页用 keyset：`WHERE 排序列 < 上一页末值 ORDER BY 排序列 DESC LIMIT 20`（与页深无关）。

## 7. SQLAlchemy 2.0 速查

```python
engine = create_engine(URL, echo=True, pool_pre_ping=True)      # 进程级单例

with engine.connect() as conn:                                   # Core
    conn.execute(text("SELECT ... WHERE x = :x"), {"x": 1}).scalar()
    conn.execute(text("...")).mappings().all()

with Session(engine) as session:                                 # ORM（一个工作单元一个 Session）
    objs = session.scalars(select(User).where(User.status == "banned")).all()
    u = session.get(User, 42)            # 主键查询，无则 None
    session.add(u); session.commit(); session.delete(u); session.commit()

# 关系加载（防 N+1）
select(User).options(selectinload(User.orders))   # 一对多：2 条 SQL（≈ prefetch_related）
select(Order).options(joinedload(Order.user))     # 多对一：1 条 JOIN（≈ select_related）

# 批量 / UPSERT（PG 方言）
session.execute(insert(User), [{...}, {...}])
insert(User).values(...).on_conflict_do_update(index_elements=["id"], set_={...})
```

**Session ≠ QuerySet**：Session=事务范围+Identity Map+dirty 跟踪；忘 commit=改动消失；Session 关闭后访问关系 → DetachedInstanceError。
**防注入**：一律 `text()` + `:param` 绑定，禁止 f-string 拼 SQL。
**窗口函数**：不能进 WHERE，`select(..., rn).subquery()` 再筛。
**一对多 joinedload**：结果要 `.unique()`。

## 8. Django ↔ SQL ↔ SQLAlchemy 对照

| Django | SQL | SQLAlchemy |
|---|---|---|
| `filter(a=1)` | `WHERE a = 1` | `.where(M.a == 1)` |
| `filter(Q(a=1)\|Q(b=2))` | `WHERE a=1 OR b=2` | `.where(or_(M.a==1, M.b==2))` |
| `exclude(...)` | `WHERE NOT ...` | `.where(not_(...))` / `!=` |
| `__in` | `IN (...)` | `.in_([...])` |
| `__range` | `BETWEEN` | `.between(a, b)` |
| `__isnull=True` | `IS NULL` | `.is_(None)` |
| `__contains` / `__startswith` | `LIKE '%x%'` / `LIKE 'x%'` | `.contains()` / `.startswith()` |
| `order_by('-x')[10:20]` | `ORDER BY x DESC LIMIT 10 OFFSET 10` | `.order_by(M.x.desc()).limit(10).offset(10)` |
| `get(pk=1)` | `WHERE id=1`（0 行也合法） | `session.get(M, 1)`（None）/ `.one()`（抛 NoResultFound） |
| `count()` | `count(*)` | `select(func.count()).select_from(M)` |
| `aggregate(Sum(...))` | `SELECT sum(...)` | `select(func.sum(...))` |
| `values().annotate(Count)` | `GROUP BY` + 聚合 | `.group_by(...)` + `func.count()` |
| annotate 后 filter | `HAVING` | `.having(...)` |
| `select_related` | JOIN 一条 SQL | `joinedload` |
| `prefetch_related` | 两条 SQL + IN | `selectinload` |
| `create()` | `INSERT ... RETURNING` | `session.add` + `commit` |
| `update(F('x')-1)` | `SET x = x - 1` | `update(M).values(x=M.x - 1)` |
| `bulk_create` | 多值 INSERT | `session.execute(insert(M), [dict...])` |
| `update_or_create` | `ON CONFLICT`（非原子→原子） | `on_conflict_do_update` |
| `Model.objects.all()` 惰性 | —（SQL 是声明） | 语句对象是值，执行显式 |
| —（QuerySet 无缓存） | — | Session Identity Map（同主键同对象） |
